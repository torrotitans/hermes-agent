# Throughput Changes Merge Skill

## When to Use This Skill

Use this skill when:
- Managing high-velocity agent development workflows
- Optimizing PR throughput for AI-generated code
- Setting up automated code review processes
- Handling flaky tests in CI/CD pipelines

## When NOT to Use This Skill

Do NOT use this skill when:
- Working on safety-critical systems requiring human review
- Team lacks confidence in automated review processes
- Regulatory requirements mandate human approval

## Core Principle

**Correction cost is low. Waiting cost is high.**

When agent throughput far exceeds human attention, traditional engineering norms become ineffective.

## Key Transformations

### PR Lifecycle Shortening

- Traditional: Days per PR
- Harness: Minutes per PR
- Target: 3.5+ PRs per developer per day

### Merge Gate Minimization

- Reduce blocking gates to minimum
- Handle flaky tests with retry mechanisms
- Trust automated validation over human review

### Agent Reviews Agent

- Humans can audit PRs but aren't required
- Agent-to-agent review is the default
- Ralph Wiggum Loop: Local review → Request additional review → Respond to feedback → Loop until approved

## Workflow

### Step 1: Configure PR Lifecycle

Set up fast PR workflows:

1. Create PR templates for agent-generated changes
2. Configure automatic branch creation
3. Set up instant validation triggers

Example PR template:

```markdown
# Automated PR

## Type
- [ ] Bug fix
- [ ] Feature
- [ ] Refactoring

## Validation
- [ ] Lint passed
- [ ] Tests passed
- [ ] Documentation updated

## Generated by
Agent: [Agent Name]
Task: [Task ID]
```

### Step 2: Minimize Merge Gates

Reduce blocking requirements:

1. Audit existing branch protection rules
2. Remove non-critical requirements
3. Configure parallel validation

Example branch protection:

```yaml
# GitHub branch protection
required_status_checks:
  contexts:
    - "Lint Check"
    - "Unit Tests"
  strict: false  # Allow updates without latest main
```

### Step 3: Implement Flaky Test Handling

Configure retry mechanisms:

1. Identify flaky tests
2. Set up automatic retry (2-3 attempts)
3. Track flakiness metrics

Example retry configuration:

```python
# pytest-rerun configuration
@pytest.mark.flaky(reruns=3, reruns_delay=5)
def test_sometimes_fails():
    # Test implementation
```

### Step 4: Set Up Agent-to-Agent Review

Configure automated review:

1. Create review agent workflow
2. Define review criteria
3. Set up approval automation

Example review workflow:

```python
# Review agent logic
def review_pr(pr_id):
    changes = get_pr_changes(pr_id)
    
    # Check coding standards
    if not check_standards(changes):
        return "REQUEST_CHANGES: Standards violation"
    
    # Check test coverage
    if not check_coverage(changes):
        return "REQUEST_CHANGES: Coverage decreased"
    
    return "APPROVE: All checks passed"
```

### Step 5: Implement Ralph Loop

Set up long-running task handling:

1. Persist work to filesystem + git
2. Intercept exit to restart with fresh context
3. Inject original prompt in new context window

Example Ralph Loop:


### Step 6: Configure Auto-Merge

Set up trusted merge:

1. Define merge criteria
2. Configure automatic merge on approval
3. Set up post-merge notifications

Example auto-merge:

```yaml
# GitHub Actions auto-merge
name: Auto Merge
on:
  pull_request:
    types: [labeled]
jobs:
  auto_merge:
    runs-on: ubuntu-latest
    steps:
      - name: Auto merge
        run: gh pr merge --auto --squash
```

## Troubleshooting

### Problem: Too many low-quality PRs

**Solution:** Strengthen pre-merge validation. Add quality gates before PR creation.

### Problem: Flaky tests block merges

**Solution:** Implement retry mechanism. Mark truly flaky tests for later fixing.

### Problem: Auto-merge introduces bugs

**Solution:** Strengthen test suite. Add smoke tests to merge criteria.
