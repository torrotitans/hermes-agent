# Execution Plan: Layer 4 - Innovation & Cognitive (Continuous Learning)

## System Context for 7B Model
**Role:** You are the execution agent tasked with building Layer 4 of the Torro Agent Architecture.
**Goal:** Implement the self-improvement loop: Data Scientist diagnostics, AI Researcher MCP integration, and AI Engineer spec generation.
**Invariants to Enforce:** 
- Strict Separation of Concerns: Diagnostics -> Research -> Spec -> Brain.
- All analysis logs must output to `/logs`.
- Docstrings must use `FN:` prefix.
- Vectorized Memory integration will be mocked with JSON until Layer 5 is fully wired.

---

## Phase 1: Diagnostics and Problem Aggregation
**Token Estimate:** ~1M Tokens
**Objective:** Parse execution failures and detect systemic drift using the Data Scientist Agent.

### Task 1.1: Error Log Parsing
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/innovation/data_scientist.py` (new)
**Action Steps:**
1. Create `engine/innovation/data_scientist.py`.
2. Define `DataScientistAgent` class with `FN:aggregate_mistake_logs`.
3. Read a mock directory `/logs` containing 3 mock `error_trace.json` files.
4. Extract the common failure mode (e.g., "Token Limit Exceeded").
**Acceptance Criteria:** The script parses JSON error logs and outputs a high-level `date_problem.md` string summarizing the systemic issue.

### Task 1.2: Efficiency Metrics Tracking
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/innovation/data_scientist.py`
**Action Steps:**
1. Implement `FN:calculate_token_efficiency`.
2. Given a mock list of `TaskCompletion` objects (with tokens_used and task_duration), calculate the average tokens per minute.
3. If tokens/minute drops below a threshold, trigger a performance alert flag.
**Acceptance Criteria:** Returns a boolean indicating whether the swarm is operating within the expected compute bounds.

## Phase 2: Autonomous Research & Specification (MCP)
**Token Estimate:** ~1M Tokens
**Objective:** Integrate the MCP protocol layer to fetch industry solutions for aggregated problems.

### Task 2.1: Model Context Protocol (MCP) Interface
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/innovation/researcher.py` (new)
**Action Steps:**
1. Create `engine/innovation/researcher.py`.
2. Define `AIResearcherAgent` class with `FN:query_mcp_notebooklm`.
3. Implement a mock HTTP POST request representing an MCP call to a NotebookLM endpoint, passing the `date_problem.md` string.
4. Return a mock `date_industry_analysis_report.md` string.
**Acceptance Criteria:** The function successfully constructs the MCP payload and returns the mock analysis report.

### Task 2.2: Architectural Specification Engineering
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/innovation/ai_engineer.py` (new), `engine/innovation/researcher.py`
**Action Steps:**
1. Create `engine/innovation/ai_engineer.py`.
2. Define `AIEngineerAgent` class with `FN:generate_technical_spec`.
3. Take the `date_industry_analysis_report.md` from Task 2.1.
4. Format it into a strict Pydantic model `TechnicalSpec` representing actionable tasks for Layer 1.
5. Serialize the Pydantic model to a `date_spec.md` string.
**Acceptance Criteria:** The Engineer agent successfully transforms a prose report into a structured, actionable specification markdown document.
