# Execution Plan: Layer 2 - Reporting (Enterprise Collaboration)

## System Context for 7B Model
**Role:** You are the execution agent tasked with building Layer 2 of the Torro Agent Architecture.
**Goal:** Implement the Project Manager and Business Analyst agents that track swarm progress, synchronize with Jira, and generate executive summaries.
**Invariants to Enforce:** 
- Strong Typing: All schemas must use Pydantic.
- Configuration: Externalized Config (`config.ini`) only. No hardcoded Jira tokens.
- No `print()` statements. Use `logger.info("FN:...")`.
- Tests must be binary (Pass/Fail) targeting real endpoints ideally.

---

## Phase 1: Bi-Directional Jira Synchronization
**Token Estimate:** ~1M Tokens
**Objective:** Implement the Project Manager Agent to sync execution states with Atlassian Jira.

### Task 1.1: Jira API Client Scaffold
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/config.py`
**Action Steps:**
1. Create `engine/reporting/jira_client.py`.
2. Define a Pydantic schema `JiraTicket` with fields: id, status, description, priority.
3. Define `JiraClient` class with `FN:fetch_ticket` and `FN:update_ticket_status`.
4. Use the `requests` library to make API calls using auth parameters pulled from `config.py`.
**Acceptance Criteria:** The client successfully compiles. Mock unit tests verify that `update_ticket_status` formats the HTTP PATCH request correctly.

### Task 1.2: Implement Project Manager Polling
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/reporting/project_manager.py` (new), `engine/reporting/jira_client.py`
**Action Steps:**
1. Create `engine/reporting/project_manager.py`.
2. Define `ProjectManagerAgent` class.
3. Implement `FN:poll_execution_status`. This method mocks checking Layer 3 execution state (e.g., "Build Failed") and calls `JiraClient.update_ticket_status` to reflect the failure.
4. Implement `FN:check_priority_escalation` to listen for Jira tickets that transition to "CRITICAL" status.
**Acceptance Criteria:** When a mock failure is injected into `poll_execution_status`, it correctly logs an update to the Jira API.

## Phase 2: Executive Reporting Generation
**Token Estimate:** ~1M Tokens
**Objective:** Build the Business Analyst Agent to convert raw Git/Execution logs into business-readable value summaries.

### Task 2.1: Parse Technical Telemetry
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/reporting/business_analyst.py` (new)
**Action Steps:**
1. Create `engine/reporting/business_analyst.py`.
2. Define `BusinessAnalystAgent` class.
3. Implement `FN:parse_technical_logs`. This function accepts a raw string of git diffs and python tracebacks.
4. Use basic keyword extraction to identify the affected systems (e.g., "UI", "Database", "Authentication").
**Acceptance Criteria:** Passing a mock git diff output returns a structured Pydantic object indicating the systems affected.

### Task 2.2: Generate Value Summary Markdown
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/reporting/business_analyst.py`
**Action Steps:**
1. Implement `FN:generate_executive_summary` in `BusinessAnalystAgent`.
2. Take the structured object from Task 2.1 and format it into a Markdown report.
3. The report must include sections: "Business Value Delivered", "Systems Affected", and "Blockers".
4. Ensure the output strictly adheres to a professional, objective tone (Torro Principle 17).
**Acceptance Criteria:** The method outputs a properly formatted Markdown string that clearly states business value without using deep technical jargon.

### Task 2.3: Integrate Reporting Hooks
**Token Budget:** 150k Tokens | **Time Estimate:** 5-10 Minutes
**Inputs Needed:** `engine/reporting/main.py`
**Action Steps:**
1. Create `engine/reporting/main.py` (Rule 16: Module Sanity entry point).
2. Write a CLI wrapper that allows running the reporting agents locally: `python main.py --mode=sync_jira` and `python main.py --mode=generate_report`.
3. Display the ASCII status banner at execution.
**Acceptance Criteria:** Executing `python engine/reporting/main.py --mode=sync_jira` runs the Project Manager logic and exits gracefully.
